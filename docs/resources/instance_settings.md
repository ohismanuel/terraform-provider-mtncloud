# mtncloud_instance_settings

Day-2 settings of an instance that something else owns, such as a VM a catalog order made (`instance_ids` of `mtncloud_wireguard_vpn`, `mtncloud_postgresql` and the other orders). It adopts the instance and changes it in place; destroy only stops tracking it, and the owner still deletes it. For now it manages the plan (size); a setting left out isn't managed.

## Example Usage

```terraform
resource "mtncloud_wireguard_vpn" "vpn" {
  name             = "wg-1"
  project          = "web-prod"
  plan             = "G1S2"
  root_volume_size = 20
  networks         = ["app-net"]
  floating_ip_pool = "public-network-01"
}

# The order's inputs can't change; its VM's size can, here.
resource "mtncloud_instance_settings" "vpn" {
  instance_id = mtncloud_wireguard_vpn.vpn.instance_ids[0]
  plan        = "G2S4"
}
```

## Schema

### Required

- `instance_id` (String) ID of the instance to manage, for example `mtncloud_wireguard_vpn.vpn.instance_ids[0]`. Changing it stops managing the old instance and adopts the new one; neither is deleted.

### Optional

- `plan` (String) Size of the VM, for example `G2S4`, from the plans the instance's image offers (checked at plan time). **Changing it restarts the VM**, in place. Disks keep their size: MTN Cloud can't grow a root disk of an existing instance. Left out, the size isn't managed.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `id` (String) The instance's ID, the same as `instance_id`.
- `name` (String) The instance's name.
- `status` (String) The instance's status, for example `running`.


## Notes

- **Adopts, never deletes.** Create reads the instance and changes only what is set; destroy stops
  managing it and keeps it. The order (or whatever made it) still deletes it.
- **A resize restarts the VM.** MTN Cloud doesn't resize a running VM without a restart. Disks keep
  their size and every disk is sent with its ID, so nothing is added or removed.
- **Drift.** A plan changed in the console reads back as the real one, and the next apply puts the
  configured plan back.
- **Instance deleted by its owner.** The next refresh drops it from state, and the plan then fails
  with "Instance not found" until `instance_id` names an instance that exists.
- **Not yet managed** (B-028): disks, network cards, power, security groups, floating IP, labels
  and tags.
